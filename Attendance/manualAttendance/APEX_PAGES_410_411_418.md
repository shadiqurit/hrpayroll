# Manual Attendance: Register 410, Entry 411, Approval 418

These are the supplied application page numbers. The SQL sources now use their
actual prefixes. Apply these settings in APEX Page Designer after installing
`INSTALL_MANUAL_APPROVAL.sql`. No deployed page export or live APEX connection
was supplied, so the files describe and supply the page changes to apply.

## Page 410 — Manual Attendance Register

Keep the register on Page 410. Configure three report regions:

| Region | SQL Source | Link destination |
| --- | --- | --- |
| My Manual Attendance | `apex_applicant_report.sql` | Page 411, `P411_ID = ID` |
| Pending Manual Attendance | `apex_pending_inbox.sql` | Page 418, `P418_ID = ID` |
| Recorded Manual Attendance | `apex_recorded_report.sql` | Page 418, `P418_ID = ID` |

The pending region includes both approval and HRD recording work. Only the
current user's actionable company assignments appear. An applicant should not
have to guess who is holding a request: show `STATUS_TEXT`, `PENDING_WITH`, and
`RECORDING_STATUS` in My Manual Attendance. Show employee, attendance date, times,
role and status in the pending region. Use `ID` as the application key; `DID` is
the history-row ID and must not be passed as the application key.

Each query includes `REQUEST_URL`, built with `APEX_PAGE.GET_URL`. Make an edit/
view link with **Target → URL → `#REQUEST_URL#`** and hide the `REQUEST_URL`
column. This supplies the target page, clears its cache and sets its request key
using the current application/session and APEX checksum handling. Keep Escape
Special Characters = Yes on text columns, including names, reason and status.

The **Create / Apply Manual Attendance** button should redirect to Page **411**,
Clear Cache **411**, with no `P411_ID` value. A new request must start with an
empty key. Default applicant/company come from the authenticated session through
the save package. Existing report saved layouts may need their new status
columns made visible after changing the SQL Source.

## Page 411 — Manual Attendance Entry / applicant detail

Use these item names in the Page 411 form. If existing items have different
names, map them consistently in both the form and the supplied process SQL.

| Item | Setting / use |
| --- | --- |
| `P411_ID` | Hidden application primary key, `MANUAL_ATT.ID`; protect from unchecksummed URL changes |
| `P411_ATT_DATE` | Attendance shift date; format mask `YYYY-MM-DD` |
| `P411_M_INTIME` | Optional full IN date/time; mask `YYYY-MM-DD HH24:MI` |
| `P411_M_OUTTIME` | Optional full OUT date/time; same mask, next date for overnight OUT |
| `P411_REASON` | Required, up to 200 bytes |
| `P411_COMMENTS` | Applicant comments, up to 1000 bytes |

Use `apex_request_detail.sql` for the authorized detail query and
`apex_request_history.sql` for the read-only history region. Both bind `P411_ID`.
For an existing key, refuse the page if the authorized detail query finds no row;
do not fall back to loading `MANUAL_ATT` by ID alone. A new form has no key and
initializes empty entry fields. Keep employee/company/status fields read-only.

For existing and new entry fields, set **Read Only → NOT Exists (SQL Query)**
using `apex_entry_edit_condition.sql`. Use the same file with **Exists (SQL Query)**
for the create/save/forward/draft buttons. It permits new own-company entries
and the applicant's editable new-workflow drafts. Submitted requests and their
history are read-only. Form display conditions complement the package's checks.

Replace the form's automatic DML with the package processes below. Disable the
old insert/history/forward processes so only one save and one route execute.
Keep form initialization, item validation and successful navigation as needed.

| After Submit process | Source | Server-side condition |
| --- | --- | --- |
| Save / Submit Manual Attendance | `apex_save_submit.sql` | PL/SQL Expression below |
| Delete Manual Draft | `apex_delete_draft.sql` | When Button Pressed = `DELETE_MANUAL` |

For the save/submit process, leave When Button Pressed empty and use:

```sql
apex_application.g_request IN ('CREATE', 'APPLY', 'SAVE', 'FORWARD', 'SAVE_DRAFT')
```

Like leave, **CREATE / APPLY / SAVE / FORWARD save and submit the route**.
**SAVE_DRAFT** alone saves without submission. Do not retain a FORWARD-only
condition. Required input validations should apply to these five requests only;
they must not block Cancel or Delete. `DELETE_MANUAL` has Execute Validations = No
and is excluded from save/submit. Show it only for an existing own-company draft
without history; the package checks eligibility again. Legacy drafts without
history can be deleted/recreated but cannot be edited/submitted as new routes.

After a successful save/submit/delete, branch to Page **410** and clear Page
**411** cache. Cancel returns to Page 410 without running either process. If
Page 411 is a modal dialog, close it on success instead; on Page 410's Dialog
Closed event, refresh the register and pending regions. Keep the key in session
on validation failure so the user can correct the form. Let APEX commit success;
do not add an internal commit to the package or process.

## Page 418 — Manual Attendance Approval / HRD recording

Use the existing approval page for both decisions and the final HRD record.

| Item | Setting / use |
| --- | --- |
| `P418_ID` | Hidden application key, **MANUAL_ATT.ID** |
| `P418_DID` | Optional existing history-form key; never substitute it for `P418_ID` |
| `P418_ACTION` | Select list with `Approve;APPROVE` and `Reject;REJECT` |
| `P418_ACTION_COMMENTS` | Optional action comments, up to 300 bytes |

The Page 410 inbox links pass the application ID to `P418_ID` and clear Page
418 cache. If an existing history-backed form also requires `P418_DID`, set a
declarative link to Page 418 with items `P418_ID,P418_DID` and values `#ID#,#DID#`;
preserve the distinction between parent and history keys. Use
`apex_approval_detail.sql` for request details and `apex_approval_history.sql`
for history. Both use `P418_ID` and enforce company/view access. Reject a missing
or unauthorized application before rendering its form.

Keep all request and approval-history data read-only. Disable Automatic Row
Processing on this page and every old forwarding/status-update process. The
package locates and locks the authenticated actor's pending history row; the
page must not directly update that row or choose an actor from an editable item.

Configure the action controls and processes as follows:

| Control / process | Configuration |
| --- | --- |
| `P418_ACTION` and approval `SUBMIT` button | Exists (SQL Query): `apex_approval_condition.sql` |
| Approval After Submit process | `apex_approval_action.sql`; When Button Pressed = `SUBMIT` |
| Approval action required validation | When Button Pressed = `SUBMIT` only |
| HRD `RECORD` button | Exists (SQL Query): `apex_record_condition.sql` |
| HRD After Submit process | `apex_record_action.sql`; When Button Pressed = `RECORD` |

HRD recording must not require `P418_ACTION`, and must not run the approval
process. Only a `PENDING` RP/final step can approve/reject; only a `PENDING`
`LEAVE_RECORD` step after final approval can record. These conditions are for
display; `TAKE_ACTION` repeats the route/company/actor/status checks on submit.

After success return to Page **410**, clearing Page **418** cache, so the pending
region no longer shows a completed action. If Page 418 is modal, close it and
refresh all three Page 410 regions on Dialog Closed. Cancel/Back returns to
410 without processing. Reopening a completed assignment remains read-only.

## Verify in APEX

1. Create from 410: Page 411 opens with an empty key. Save Draft appears once in
   the applicant register and does not enter an approval inbox.
2. Open that draft from 410 and press Save/Apply/Forward: the route is created
   once and the register displays the current pending person/role.
3. The assigned approver opens Page 418 from Pending Manual Attendance. RP
   recommendation leaves the request pending with the final alternatives.
4. One eligible final approver approves: the corrected attendance is applied,
   status becomes Approved, and HRD sees the request in the pending region.
5. HRD opens Page 418 and records without selecting an approval action. The
   pending row disappears; the recorded report and applicant status update.
6. Check rejection, a completed/stale link, another user's key, a mismatched
   company and Cancel/Delete. None should save or route an unintended request.

The database installer and Oracle runtime test are described in `README.md`.
This page wiring does not require a different approval policy or new page IDs.
